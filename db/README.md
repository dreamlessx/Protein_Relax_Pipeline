# BM5.5 Benchmark Database

Canonical SQLite store for Rosetta + MolProbity + TM-score data generated by the BM5.5 benchmark pipeline.

## Design

- **SQLite single file** (stdlib, portable, GitHub-friendly)
- **Star schema** with narrow dimension tables + wide `rosetta_metrics` fact table
- **Source of truth on ACCRE**; laptop + GitHub get read-only snapshots
- **QC at ingest**: exact dupes + legacy sources filtered; conflicting/missing/orphan rows quarantined
- **Derivative tables as views** (`v_per_target_mp_means`, `v_cell_summary`) plus materialized TSV for legacy script compatibility

## Schema

See [`sql/schema.sql`](sql/schema.sql). Tables:

| Table | Purpose | Rows (expected) |
|---|---|---|
| `build_runs` | Provenance: one row per snapshot with git commit, manifest hash, QC status | ~10 |
| `targets` | 257 BM5.5 complexes, difficulty class, non-standard flag | 257 |
| `pipelines` | blue, green | 2 |
| `sources` | 7 source buckets (af_relaxed, af_unrelaxed, amber_af, amber_boltz, amber_crystal, boltz, crystal) | 7 |
| `protocols` | 6 Rosetta protocols with score weights + move set | 6 |
| `rosetta_metrics` | Wide fact table: MolProbity metrics per run | 416,340 at 100% lock |
| `prerosetta_metrics` | Pre-Rosetta MP on input structures | 27 per target per pipeline |
| `tm_scores` | Pre + post Rosetta TM-score | 27 pre + 416,340 post per pipeline |
| `qc_quarantine` | Bad rows by bucket (exact_duplicate, conflicting_duplicate, missing_key, orphan_row, invalid_enum, coverage_gap) | variable |

## Build (idempotent, one command)

```bash
cd /data/p_csb_meiler/agarwm5/red_analysis   # ACCRE canonical location
conda activate red_analysis

python db/scripts/build_db.py \
    --raw-root /data/p_csb_meiler/agarwm5/red_analysis/metrics \
    --out      db/bm55.sqlite \
    --snapshot $(date +%Y-%m-%d)
```

Emits:
- `bm55.sqlite` - single canonical file
- Quarantine table populated with all skipped rows + coverage gaps
- `build_runs` row with git commit + manifest hash + qc_status ∈ {pass, warn, fail}

## Query examples

```sql
-- Per-target means (equivalent to per_target_mp_means.tsv)
SELECT * FROM v_per_target_mp_means WHERE pipeline_id='blue' AND protocol_id='dualspace_beta';

-- Cell summary (equivalent to rosetta_protocol_summary.tsv)
SELECT * FROM v_cell_summary WHERE protocol_id='dualspace_beta' ORDER BY pipeline_id, source_id;

-- Coverage audit
SELECT target_id, pipeline_id, COUNT(*) AS n
FROM rosetta_metrics GROUP BY target_id, pipeline_id HAVING n < 810
ORDER BY n ASC;

-- Quarantine breakdown
SELECT bucket, COUNT(*) FROM qc_quarantine GROUP BY bucket;
```

## Data integrity guarantees

1. **Legacy collision filter**: rows with `src_type IN {amber_af_relaxed, amber_boltz_relaxed}` are skipped at ingest (prevents Jan-2026 naming-collision contamination of amber_af / amber_boltz source buckets).
2. **Exact-duplicate detection**: natural key `(target, pipeline, src_type, protocol, rep)` checked at load; duplicates counted and skipped.
3. **Foreign key enforcement**: every `rosetta_metrics` row must resolve to a valid target_id + pipeline_id + source_id + protocol_id.
4. **Coverage gap tracking**: cells with `COUNT(*) < 810` logged into `qc_quarantine` bucket=`coverage_gap`.
5. **Build provenance**: every row tagged with `snapshot_id`, FK to `build_runs` with git commit + raw manifest hash.
